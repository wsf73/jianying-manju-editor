# 字字动画 data.ini 的两代格式

`data.ini` 是 INI，section 固定为 `[image_viewer]`，每行 `<hash> = <URL-safe base64 的 Python pickle>`。
解码方式：`-`→`+`、`_`→`/`，剥掉非 base64 字符，补 `=` 到 4 的倍数，再按 UTF-8（替换错误字节）读。

解码后是一坨 pickle 结构，**真正有用的分镜文本在 `paperwork` 字段里**。
不同时期生成的工程格式不一样，`zizi.js` 会自动识别（`parseEntry`）。

## 格式 A（2026-09 早期）

```
第一集：锁上院门，揣着六十万进城
本组总时长：11s
人物：周德福，李秀兰
场景：老宅堂屋｜内｜日
镜头 1 / SC1（0-2 秒）：
【画面】...
【台词】周德福：“...”
镜头 2 / SC2（2-6 秒）：
...
```

- 时间：每个镜头**直接给出绝对起止秒**。
- 台词：`【台词】` / `【画外音】` / `【OS】`，角色名和引号在一起。
- 人物：有独立的 `人物：` 字段。

## 格式 B（2026-09 后期及以后）

```
第一集：离婚协议甩在脸上
_::~OUTPUT_START::~_
本组总时长：11s
背景：...
看点：...
元素数：出场人物2＋场景1＝3
场景1：苏玉晴家土院｜外｜日
[画面] 时长2秒（0字台词）。
画面：...
[画面] 时长4秒（17字台词）。
画面：马涛西装革履...
台词：马涛：玉晴，考虑得咋样了？
```

- 时间：**只给每格时长，起始时间靠累加**。累加结果与本组总时长一致（实测 565/565 条误差 0）。
- 台词：`台词：<角色>：<内容>`，角色名可能是 `众人（画外音）`、`陈默（OS）`、`马涛（画外对白延续）`。
- **没有 `人物：` 字段** → 用 characters.json 的姓名/别名在整个正文里扫，谁出现算谁出场。
- 集标题常常在正文**之前**（分隔符前），只有换集时才出现，所以要在锚点前 600 字里找。

## 格式 B 的坑（都踩过）

1. **锚点要取靠前的那个**。同一个 pickle 的后面字段（`last_gen_paperwork` 等）里也可能出现
   `_::~OUTPUT_START::~_`，如果无脑用分隔符切，会把正文切没，导致该条解析出 0 个镜头
   （本项目 97/567 条中招，17%）。
   正确做法：取 `本组总时长` 和分隔符中**位置更靠前**的那个当锚点。
2. **`时长` 两个字可能省略**：同一批里既有 `[画面] 时长4秒（17字台词）。` 也有 `[画面] 4秒（17字台词）。`。
   正则要写成 `\[画面\]\s*(?:时长\s*)?([\d.]+)\s*秒`。
3. **总时长的单位可能是 `s` 也可能是 `秒`**：`本组总时长：11s` / `本组总时长：11秒`。正则要两种都吃。
4. **正文在第一个控制符处结束**。pickle 的结构字节解码后是乱码/控制符，
   把 `[\u0000-\u001f]`（保留换行）和 `\ufffd` 归一成一个哨兵字符，然后从哨兵处截断，就能拿到干净的正文。
5. **data.ini 里会混入非分镜的键**：本项目末尾有 `origin_text`（空）和 `reference_result`（二进制）。
   解析不出来就返回 `null` 跳过，**并改用 order 建索引**（`Z.itemIndex`），
   绝对不能用 `items[片段号-1]` 这种数组下标。
6. 写诊断文件时先做一次可打印字符净化，否则 `read` 工具会判定成二进制文件读不了。

## 映射草稿片段

视频文件名 `%04d_<hash>_%s_%s.mp4` 的前 4 位数字就是 data.ini 的条目号（1 起）。
用文件名里的 hash 去比对解码出来的 `unique_name`，必须 **100% 匹配**才算对上了工程。
本项目 565 段 / 565 条、0 不匹配。
